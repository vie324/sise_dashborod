# カウンセリング（新規のお客様）— Google フォームとの連携

新規のお客様が来店時に答える **カウンセリングの Google フォーム** の回答を、ダッシュボードの
**施術ツール →「カウンセリング」** に表示する。以前のダッシュボードの「カウンセリング」画面を、今の画面に作り直したもの。

## 1. しくみ

```
お客様が Google フォームを送信
  → 店舗ごとの回答シート（1つのスプレッドシート）
  → GAS（gas/counseling.gs）をウェブアプリとして公開
  → ダッシュボードのサーバー（/api/db?table=counseling）だけが呼ぶ
  → 施術ツール → カウンセリング（30秒ごとに自動で確認）
```

- **読み取りのみ**。回答を書き換えることはない
- GAS の URL と合言葉は **サーバーにだけ** 保存する（`dash_config` の `counseling.config`、または環境変数）。
  一般の設定 API（`dashConfig`）からは読めず、スタッフの端末にも送らない
- 見える範囲: スタッフ・店長・マネージャーは **所属・管轄の店舗のシートだけ**、オーナー・管理者は全店舗
- 電話番号・メールアドレスは画面で使わないため、サーバーで外して返す
- 本番は `REQUIRE_ADMIN_AUTH=true`（URL 無しのアクセスにログインを求める）にしておくこと（RUNBOOK §3）

## 2. 画面でできること

| | |
|---|---|
| カウンセリングシート | 店舗の新しい回答（最大 50件）。お客様がフォームを送ると 30秒以内に「NEW」で届き、お知らせが出る。お名前で過去の回答も検索できる |
| お客様の内容 | 施術の前に確認すること（手術歴・治療中・アレルギー・美容整形・妊娠/特定疾患。「いいえ」「なし」は出さない）、生年月日（年齢）・職業・お住まい・目標時期、施術のご要望、ご利用経験のある施術、ご来店のきっかけ |
| 01 ヒアリング＆プラン診断 | フォームで選んだお悩みを 16 のチェック項目に自動で反映（「フォーム」の印）。施術後の評価（10 項目）を付けると、しっかり / おすすめ / お手軽 の 3 プランを提案。カードかセラピスト変更で選び直せる |
| 02 改善シミュレーション | 通い方ごとの改善のイメージ（月4回 → 継続 / 月2回へ / 月1回へ、月2回 → 継続 / 月1回へ、1回のみ） |
| 03 プラン選択 | 料金表。診断で選んだプランと回数を強調 |
| そのほか | コンセプト説明・サブスク会員 3つのポイント・当日契約で3つの特典・プラン選びのポイント |
| 引き継ぎ | 「このお客様で姿勢分析」「施術レポート」でお客様名を入れた状態で開く |

チェック項目・判定・プランの金額は `shared/counseling.js` にまとめてある（以前の画面と同じ内容）。
金額や特典の文言を変える場合は `shared/counseling.js` と `src/features/care/counseling/PlanGuide.jsx` を更新する。

GAS につながっていない時も、チェック・おすすめプラン・シミュレーション・料金表は手で使える。

## 3. 準備（オーナー・管理者）

1. カウンセリングのフォームの回答先を 1つのスプレッドシートにし、シート名を次のとおりにする
   （`カウンセリング回答_本厚木店` / `_大和店` / `_横浜店` / `_町田店` / `_川口店`）
2. スプレッドシートの **拡張機能 → Apps Script** に `gas/counseling.gs` を貼り付けて保存
3. Apps Script の **プロジェクトの設定 → スクリプト プロパティ** に `DASHBOARD_TOKEN`（合言葉。推測されにくい 32 文字くらいのランダムな文字列）を追加
4. **デプロイ → 新しいデプロイ**（種類: ウェブアプリ / 実行するユーザー: 自分 / アクセスできるユーザー: 全員）→ 表示された URL（`…/exec`）をコピー
5. ダッシュボードの **設定 → カウンセリング** に URL と合言葉を貼り付けて保存 →「接続テスト」で各店舗が「読めます」になるか確認
6. **店舗の対応付け**: ダッシュボードの店舗名がフォームの店舗名と同じ（「本厚木店」など）なら自動で対応する。違う名前の店舗は選んで保存する
7. 以前の URL を使わなくなったら、Apps Script の **デプロイを管理** で古いデプロイを **アーカイブ** する（その URL は止まる）

> GAS のウェブアプリは「アクセスできるユーザー: 全員」なので、**URL を知っていれば誰でも呼び出せる**。
> 合言葉（`DASHBOARD_TOKEN`）を設定すると、合言葉の無い呼び出しには回答を返さなくなる。必ず設定すること。
> 以前のダッシュボードは画面のコードに GAS の URL を埋め込んでいた（このリポジトリは公開のため、過去のコミットからも見える）。
> 新しいデプロイに切り替えて、古いデプロイはアーカイブしておく。

環境変数で設定することもできる（設定画面で保存した値が優先）:

| 変数 | 用途 |
|---|---|
| `COUNSELING_GAS_URL` | GAS のウェブアプリの URL（`…/exec`） |
| `COUNSELING_GAS_TOKEN` | 合言葉（GAS の `DASHBOARD_TOKEN` と同じ文字列） |

## 4. 困ったとき

| 症状 | 確認すること |
|---|---|
| 「カウンセリングフォームとの連携が未設定です」 | 設定 → カウンセリング で URL を保存したか |
| 「この店舗はカウンセリングフォームと対応付けられていません」 | 設定 → カウンセリング → 店舗の対応付け（名前が違う店舗は手で選ぶ） |
| 接続テストで「GAS の応答を読み取れませんでした」 | デプロイの「アクセスできるユーザー」が「全員」か。URL が `/exec` で終わっているか |
| 「GAS の合言葉が一致しません」 | 設定画面の合言葉と、GAS のスクリプト プロパティ `DASHBOARD_TOKEN` が同じか |
| 「シート "…" が見つかりません」 | スプレッドシートのシート名（§3-1） |
| お悩みがチェックに入らない | フォームの選択肢の言葉が `shared/counseling.js` の `formLabels` に無い（画面では「項目なし」と出る）。必要なら言葉を足す |
| 届くのが遅い | 画面は 30秒ごと、サーバーは同じ店舗の取得を 20秒まとめている。「今すぐ確認」（⟳）で取り直せる |

GAS の列の名前と中身が入れ替わって届くため、`pregnancyCheck` の回答を「美容整形」、`cosmeticSurgery` の回答を
「妊娠・特定疾患」として表示している（以前の画面と同じ）。回答の言葉（妊娠・授乳 / ヒアルロン・ボトックスなど）で
はっきり分かる場合はそちらを優先する（`api/_lib/counseling.js` の `cautionsOf`）。

## 5. 開発

- `npm run dev:local` は `COUNSELING_GAS_URL` が無ければ疑似 GAS（`scripts/dev/gas-fake.mjs`、架空のお客様）を使う。
  中央店・駅前店は名前が違うので、設定 → カウンセリング で本厚木店などに対応付けてから施術ツールを開く
- 新しい回答が届く動きを試す: `curl "http://localhost:3000/__fake-gas/exec?type=counseling&action=_submit&store=honatsugi&name=新井%20ゆい"`
- テスト: `test/counseling.test.js`（チェック項目の対応・おすすめプラン・見える範囲・設定・合言葉・接続テスト）
