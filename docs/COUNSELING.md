# カウンセリング（新規のお客様）— SalonOne の予約・Google フォームの回答・お客様へのご説明

施術ツール →「カウンセリング」は、**SalonOne の今日の予約からお客様を選び**、カウンセリングの後に
**タブレットやスマホをお客様に向けて見せる全画面のご説明**（コンセプト・改善のイメージ・おすすめプラン・料金・特典）を行う画面。

**Google フォーム（GAS）でカウンセリングシートを取っている店舗**は、フォームの回答も読み取り、
お客様が選んだお悩みを**チェックに自動で入れ**、記入された内容（施術前の確認・お悩み・ご要望・改善したい時期など）を大きく表示する。
SalonOne の問診票を使う店舗はフォームとつながず（設定で「連携しない」）、これまでどおり予約から始める。

## 1. 流れ

```
来店 → カウンセリングシート（SalonOne の問診票、または Google フォーム）
  → 施術ツール → カウンセリング →「本日のお客様」からお客様を選ぶ（SalonOne の今日の予約）
      └ フォームの店舗: 同じお名前の回答があれば「シートあり」→ 選ぶとお悩みが自動でチェックに入る
  → お悩み・施術後の評価をチェック → おすすめプラン（しっかり / おすすめ / お手軽）
  →「お客様に説明する」→ 全画面のご説明をお客様に見せる → まとめ（選んだプラン・本日の特典・次回の目安）
```

| 画面 | 内容 |
|---|---|
| 本日のお客様 | SalonOne の今日の予約。初回のお客様（SalonOne の区分「新規」）を先に出し、2回目以降のお客様は「すべての予約」から。時刻・状態（予約 / 来店中 / 会計済み）・担当・媒体・この来店での契約（「ご契約」）。キャンセルは出さない。1分ごとに自動で確認（⟳ ですぐ確認）。予約に無いお客様は「予約に無いお客様で始める」 |
| フォームの回答（フォームの店舗だけ） | 店舗の新しい回答（最大 50件）。30秒ごとに自動で確認し、お客様がフォームを送ると「NEW」とお知らせが出る。お名前で過去の回答も探せる。回答を選ぶと、同じお名前の今日の予約と一緒に開く（予約が無ければ回答だけで始める） |
| 選んだお客様 | ご説明の画面に出すお名前（SalonOne のお名前の姓が入る。手で直せる）。「このお客様で姿勢分析」「施術レポート」でお名前を引き継ぐ。選んだ後に同じお名前の回答が届くと「◯◯ 様のカウンセリングシートが届きました」→「反映する」 |
| カウンセリングシート（フォームの店舗だけ） | §2 |
| ヒアリング＆プラン診断 | お悩み 16項目（小顔矯正・姿勢矯正・骨盤矯正）と施術後の評価 10項目（セラピスト用。お客様には見せない）から 3つのプランを提案。カウンセリングシートから入ったチェックには印（📄）。カードか「セラピスト変更」で選び直せる |
| お客様へのご説明 | 章を選んで途中から始められる（はじめに / コンセプト / 改善のイメージ / プラン / 特典 / まとめ）。画面の下の「お客様に説明する」「プランから」からも開く |

## 2. Google フォームの回答（フォームを使う店舗だけ）

### 予約との結びつけ・お悩みの自動チェック

- 今日の予約と回答を**お名前**で結びつける（空白・全角半角・「様」の違いは同じとみなす。**3日以内**の回答だけ。同じ人は新しい回答）。
  結びついた予約には「シートあり」と、フォームで選ばれたお悩みが一覧に出る
- お客様を選ぶと、フォームで選ばれたお悩みを **16 のチェック項目に自動で入れる**（フォームの言葉 → 項目の対応は `shared/counseling.js` の `formLabels`）。
  入れるのは 1つの回答につき 1回だけ。スタッフが付けた・外したチェックはそのまま
- 項目に無いお悩み（「頭痛」など）は、カウンセリングシートのお悩みに「（チェック項目なし）」と出る
- SalonOne のキーが**お名前を返さない設定**（「個人情報を含めない」）では予約と自動で結びつかない。
  「フォームの回答」のタブから回答を選ぶ（同じお客様の予約を選び直す必要はない）
- 読み方の違う書き方（漢字 / ひらがな）や旧姓は結びつかない。その時も「フォームの回答」から選ぶ

### カウンセリングシートの表示（スタッフの画面）

| | |
|---|---|
| 施術の前に確認してください | 手術歴・治療中・アレルギー・美容整形・妊娠/特定疾患。赤い枠で大きく出す（「いいえ」「なし」は出さない）。無ければ「施術の前に確認することはありません」 |
| お悩み | フォームで選ばれたお悩み（チェックに入ったものに ✓） |
| 施術のご要望 | お客様が書いた文章をそのまま |
| 改善したい時期 | 「3ヶ月以内」「結婚式までに」など |
| お客様のこと | 年齢（生年月日から）・ご職業・お住まい・ご来店のきっかけ・ご利用経験のある施術 |

電話番号・メールアドレスはサーバーで外して返す（画面には来ない）。

### お客様へのご説明に出すもの

回答があるお客様は、表紙の次に **「ご記入いただいた内容」**（お悩み・改善したい時期・施術のご要望）のスライドが入り、
「改善のイメージ」に **「◯◯ 様の目標」**（改善したい時期）が出る。
**施術前の確認（手術歴・治療中など）・年齢・職業・住所はお客様向けの画面に出さない**（スタッフの画面だけ）。

## 3. お客様へのご説明（全画面）

1枚ずつ大きく見せるスライド。**下のボタン・左右のスワイプ・← → キー**で進む／戻る。章の名前を押すとその章へ。Esc か × で閉じる。

| # | スライド | 内容 |
|---|---|---|
| 1 | 表紙 | 「◯◯ 様」・ごあいさつ・担当・日付 |
| (2) | ご記入いただいた内容 | **カウンセリングシートの回答があるお客様だけ**。お悩み・改善したい時期・施術のご要望を大きく |
| 2 | お悩み | からだの図（お悩みのある部位が光る）と 16項目。**お客様にタップしていただける**（スタッフの画面のチェックと同じ） |
| 3 | なぜ繰り返すのか | 悩みの連鎖（日常の姿勢・癖 → 骨格の歪み → 筋肉の硬化 → インナーマッスル低下）と一般的な対処（一時的） |
| 4 | si'se のアプローチ | 連鎖のそれぞれへの対応（正しい姿勢指導・骨格矯正・ボディケア・セルフケア指導） |
| 5 | 改善のイメージ | 通い方ごとの改善の曲線（おすすめの通い方を太く。「施術1回のみ」は約2週間で元に戻る）。「◯◯ 様の目標」（回答があれば）と「まずは3ヶ月」。※イメージ・個人差の注記つき |
| 6 | おすすめプラン | 3つ（真ん中がおすすめ）。月額・1回あたり・通常料金との差（毎月◯円おトク）。タップで選べる |
| 7 | 料金プラン | 全プランの料金表。行をタップで選べる。入会費 → 本日のご契約で 0円 |
| 8 | 会員のポイント | 繰越・セルフケア指導・シェア |
| 9 | 本日の特典 | 入会費 0円・解約費無料（翌月から変更・解約OK）・指名料ずっと無料 |
| 10 | まとめ | 選んだプラン（月額・1回あたり）・本日ご契約の特典・次回のご来店の目安・プラン選びのポイント |

- テーマ（ダーク表示）に関係なく**明るい配色**で見せる。文字の大きさは画面の大きさに合わせて変わる（スマホ・iPad 縦横・PC）
- 対応している端末では「全画面」ボタンでブラウザの枠も消せる。ご説明中は画面が暗くならない（Screen Wake Lock）
- お客様に見せない情報（施術後の評価・顧客番号・施術前の確認・年齢などのプロフィール）はご説明の画面に出さない
- 「通常の料金」は料金表の「1回の料金 × 回数」。1回あたりは「月額 ÷ 回数」

## 4. 準備（オーナー・管理者）

### SalonOne（全店舗）

1. SalonOne 連携（`SALONONE_API_KEY`）を済ませる（[SALONONE.md](SALONONE.md)）。キーが無い間はデモの予約で動く（画面に「デモ」）
2. 設定 → SalonOne連携 で **店舗を対応付けて保存**（対応付けの無い店舗は予約が出ない。「予約に無いお客様」としては使える）
3. お客様の**お名前も一覧に出したい場合**（フォームの回答と予約を自動で結びつけたい場合も）は、SalonOne の「API連携」でキーを
   **「個人情報を含める」** で発行し直し、Vercel の `SALONONE_API_KEY` を差し替えて再デプロイ
   - 含めないキー（既定）では、お名前の代わりに **顧客番号**（SalonOne の顧客管理と同じ番号）で表示する。ご説明の画面のお名前は手で入れられる
   - 含めるキーは、キーが外に出ると顧客名簿が流出する。キーはサーバーの環境変数にだけ置き、画面・ブラウザには出さない（このダッシュボードが画面に返すのは、今日の予約のお客様のお名前だけ。電話番号・予約メモは返さない）

見える範囲: スタッフ・店長・マネージャーは**所属・管轄の店舗の予約・回答だけ**、オーナー・管理者は全店舗（サーバーで判定）。

### Google フォーム（フォームでカウンセリングシートを取っている店舗だけ）

```
お客様が Google フォームを送信 → 店舗ごとの回答シート（1つのスプレッドシート）
  → GAS（gas/counseling.gs）をウェブアプリとして公開 → ダッシュボードのサーバー（/api/db?table=counseling）だけが呼ぶ
```

1. カウンセリングのフォームの回答先を 1つのスプレッドシートにし、シート名を次のとおりにする
   （`カウンセリング回答_本厚木店` / `_大和店` / `_横浜店` / `_町田店` / `_川口店`）
2. スプレッドシートの **拡張機能 → Apps Script** に `gas/counseling.gs` を貼り付けて保存
3. Apps Script の **プロジェクトの設定 → スクリプト プロパティ** に `DASHBOARD_TOKEN`（合言葉。推測されにくい 32 文字くらいのランダムな文字列）を追加
4. **デプロイ → 新しいデプロイ**（種類: ウェブアプリ / 実行するユーザー: 自分 / アクセスできるユーザー: 全員）→ 表示された URL（`…/exec`）をコピー
5. ダッシュボードの **設定 → カウンセリングフォーム** に URL と合言葉を貼り付けて保存 →「接続テスト」で各店舗が「読めます」になるか確認
6. **店舗の対応付け**: ダッシュボードの店舗名がフォームの店舗名と同じ（「本厚木店」など）なら自動で対応する。違う名前の店舗は選んで保存する。
   **SalonOne の問診票を使う店舗は「連携しない」** にする（フォームのタブ・シートの表示が出なくなる）
7. 以前の URL（以前のダッシュボードに埋め込まれていた URL）は、Apps Script の **デプロイを管理** で古いデプロイを **アーカイブ** する（その URL は止まる）

> GAS のウェブアプリは「アクセスできるユーザー: 全員」なので、**URL を知っていれば誰でも呼び出せる**。
> 合言葉（`DASHBOARD_TOKEN`）を設定すると、合言葉の無い呼び出しには回答を返さなくなる。必ず設定すること。
> 以前のダッシュボードは画面のコードに GAS の URL を埋め込んでいた（このリポジトリは公開のため、過去のコミットからも見える）。
> 新しいデプロイに切り替えて、古いデプロイはアーカイブしておく。

- **読み取りのみ**。回答を書き換えることはない
- GAS の URL と合言葉は **サーバーにだけ** 保存する（`dash_config` の `counseling.config`、または環境変数）。
  一般の設定 API（`dashConfig`）からは読めず、スタッフの端末にも送らない
- 本番は `REQUIRE_ADMIN_AUTH=true`（URL 無しのアクセスにログインを求める）にしておくこと（RUNBOOK §3）

環境変数で設定することもできる（設定画面で保存した値が優先）:

| 変数 | 用途 |
|---|---|
| `COUNSELING_GAS_URL` | GAS のウェブアプリの URL（`…/exec`） |
| `COUNSELING_GAS_TOKEN` | 合言葉（GAS の `DASHBOARD_TOKEN` と同じ文字列） |

## 5. 内容を変えるとき

| 変えたいもの | ファイル |
|---|---|
| プランの金額・回数・入会費 | `shared/counseling.js`（料金表 `PLAN_CARDS`・`ENTRY_FEE`。おすすめに出すプランの説明は `PLAN_CATALOG`） |
| お悩み・施術後の評価の項目、おすすめの判定 | `shared/counseling.js`（`CONCERN_ITEMS`・`FEEDBACK_ITEMS`・`recommendPlans`） |
| フォームのお悩みの言葉 → チェック項目の対応 | `shared/counseling.js`（`CONCERN_ITEMS` の `formLabels`。部分一致） |
| コンセプト・会員のポイント・本日の特典・プラン選びのポイントの文言 | `src/features/care/counseling/content.jsx` |
| 改善のイメージの曲線・説明 | `src/features/care/counseling/Simulation.jsx` |
| スライドの並び・見た目 | `src/features/care/counseling/present/`（`Presentation.jsx` が並びと操作、`slides.jsx` が各スライド） |
| カウンセリングシートの表示 | `src/features/care/counseling/SheetPanel.jsx`（回答の整形・施術前の確認の判定は `api/_lib/counseling.js`） |

特典やキャンペーンが終わったら `content.jsx` の `OFFERS` と、料金表の「本日のご契約で 0円」の表示（`slides.jsx` の `Prices`・`Offers`）を合わせて直す。

## 6. 困ったとき

| 症状 | 確認すること |
|---|---|
| 「この店舗は SalonOne の店舗と対応付けられていません」 | 設定 → SalonOne連携 で店舗を対応付けて保存（フォームの店舗は「フォームの回答」から始められる） |
| 予約が出ない | SalonOne の予約表にその日の予約があるか。キャンセル・無断キャンセルは出さない。初回以外は「すべての予約」 |
| お名前が出ず顧客番号になる | キーが「個人情報を含めない」設定（§4 SalonOne-3） |
| 「◯時◯分時点の予約を表示しています」 | SalonOne から取り直せず前回の値を表示中。時間をおいて ⟳ |
| 来店中・会計済みにならない | SalonOne で来店・会計の操作をしているか（予約のままの店舗は「予約」と出る） |
| 全画面ボタンが出ない | iPhone など全画面に対応していないブラウザ（ホーム画面に追加して開くと画面いっぱいに出る） |
| 「フォームの回答」のタブが出ない | 設定 → カウンセリングフォーム で URL を保存し、店舗を対応付けたか（「連携しない」の店舗には出ない） |
| 予約に「シートあり」が付かない | SalonOne のお名前とフォームのお名前の書き方が違う / キーがお名前を返さない設定 / 回答が 3日より前。「フォームの回答」から選ぶ |
| 「この店舗はカウンセリングフォームと対応付けられていません」 | 設定 → カウンセリングフォーム → 店舗の対応付け（名前が違う店舗は手で選ぶ） |
| 接続テストで「GAS の応答を読み取れませんでした」 | デプロイの「アクセスできるユーザー」が「全員」か。URL が `/exec` で終わっているか |
| 「GAS の合言葉が一致しません」 | 設定画面の合言葉と、GAS のスクリプト プロパティ `DASHBOARD_TOKEN` が同じか |
| 「シート "…" が見つかりません」 | スプレッドシートのシート名（§4 Google フォーム-1） |
| お悩みがチェックに入らない | フォームの選択肢の言葉が `formLabels` に無い（シートに「（チェック項目なし）」と出る）。必要なら言葉を足す |
| 回答が届くのが遅い | 画面は 30秒ごと、サーバーは同じ店舗の取得を 20秒まとめている。⟳ で取り直せる |

GAS の列の名前と中身が入れ替わって届くため、`pregnancyCheck` の回答を「美容整形」、`cosmeticSurgery` の回答を
「妊娠・特定疾患」として表示している（以前の画面と同じ）。回答の言葉（妊娠・授乳 / ヒアルロン・ボトックスなど）で
はっきり分かる場合はそちらを優先する（`api/_lib/counseling.js` の `cautionsOf`）。

## 7. 開発

- API: `GET /api/salonone?action=visits&storeId=<店舗ID>`（日付は常に今日。実装は `api/_lib/salonone/visits.js`）、
  `GET /api/db?table=counseling&action=stores|recent|search|detail`（フォーム。実装は `api/_lib/counseling.js`）
- `npm run dev:local`（`SALONONE_API_KEY` 無し）はデモの予約（時刻を過ぎると来店中 → 会計済み）。
  `COUNSELING_GAS_URL` が無ければ疑似 GAS（`scripts/dev/gas-fake.mjs`、架空のお客様）を使う。
  中央店・駅前店は名前が違うので、設定 → カウンセリングフォーム で本厚木店などに対応付けてから施術ツールを開く
  （デモの予約にはフォームと同じお名前のお客様がいるので「シートあり」になる）
- 新しい回答が届く動きを試す: `curl "http://localhost:3000/__fake-gas/exec?type=counseling&action=_submit&store=honatsugi&name=新井%20ゆい"`
- 疑似 SalonOne（`scripts/dev/salonone-fake.mjs`）は 1日だけの取得（from = to）にその日の予約のサンプルを返す。
  キー `test-key` は個人情報なし、`test-key-pii` はお名前つき
  ```sh
  node scripts/dev/salonone-fake.mjs --port 4100
  SALONONE_API_KEY=test-key-pii SALONONE_API_BASE_URL=http://127.0.0.1:4100/api/analytics/v1 npm run dev:local
  ```
  （設定 → SalonOne連携 で 中央店 → 101、駅前店 → 102 に対応付ける）
- テスト: `test/counseling.test.js`（おすすめプラン・料金の計算・予約の整形・見える範囲・キャッシュ・デモ）、
  `test/counseling-form.test.js`（フォームのお悩み → チェック項目・お名前での結びつけ・回答の見える範囲・設定・合言葉・接続テスト）
