# マンダラ（チャート・週報・日報）

別アプリだった「マンダラチャート週次進捗管理ツール」（リポジトリ `vie324/mandala-tool`）を、
このダッシュボードの画面 **マンダラ** に組み込んだもの。スタッフは今までのスタッフ URL のまま使える（別のログインは無い）。

- 追跡するのは **マンダラチャートと週報・日報が回っているか** だけ（チャートの記入・週報の提出・行動のチェック・フォーカスの達成）
- 売上・施術数などの数字は SalonOne（ホーム・インセンティブ・売上分析）で見るので、マンダラには **数字の入力欄を置かない**
  - チャートの目標金額（センターゴールの「◯万円」）だけは目標そのものなので持つ。今月の施術消化売上（SalonOne）を目標の横に並べて見せる（読むだけ）
- AI（Claude）が週報をレビューし、来週のフォーカスを 3つ提案する。チャート作成では項目の分類と言い換えを提案する

## 画面

スマホでは下のタブの「その他 → マンダラ」、PC では左のメニュー。ホームの上にも入口（今週の振り返り・今日の日報・チームの提出状況）を出す。

| 画面（`#/mandala/...`） | 見る人 | 内容 |
|---|---|---|
| ホーム | スタッフ URL の人 | 今週の振り返り（いちばん大きいボタン）・今日の日報・チャートの記入状況と目標（今月の SalonOne の売上つき）・今週のフォーカス・直近 8週の行動の実行率 |
| チャート `chart` | 本人 | 9×9 のマンダラ（スマホはブロックをタップで拡大・スワイプで隣へ）。今週のフォーカスは金色の枠。仲間への公開の切り替え・届いた応援 |
| 編集 `edit/:step/:theme` | 本人 | ① 目標（現状の月売上は SalonOne の直近 3ヶ月の平均を 1タップで入れられる）② 逆算 ③ 8テーマ ④ 64項目 ⑤ 分類（行動 / 数値 / 心構え・毎週チェック）+ AI の提案。テーマの番号で行き来でき、移る前に保存する |
| 週報 `review/:week` | 本人 | できた行動のチェック・今週のフォーカスの ◯× ・ひとこと振り返り・来週のフォーカス（自分で選ぶ / AI の提案を採用）・店長とのやりとり。**入力は自動で保存**。提出すると AI がレビューする |
| 日報 `daily/:date` | 日報の対象の人 | 出勤時 / 勤務中 / 退勤前のチェック・今日の振り返り・備考。自動で保存。「出納帳」「週報」などの項目からその画面をすぐ開ける |
| 仲間 `peers` | 共有がオンの時 | 公開している仲間のチャートと進み具合（集計だけ）。応援を送れる |
| チーム `team/:week` | 店長・マネージャー・オーナー | 提出状況・チャート作成・今日の日報・週報のヒートマップ（直近 8週）・店舗別・メンバーごと。店舗の切り替え・CSV |
| みんなのチャート `charts` | 同上 | 全員のセンターゴール・8テーマ・記入状況 |
| 動き `activity` | 同上 | 週報の書き始め・更新・提出、チャートの更新、日報、AI、コメント、応援を日ごとに |
| メンバー `member/:id/:tab` | 同上 | 週報（読むだけ・コメント・AI の作り直し）/ マンダラ / 日報（コメント）/ 動き。日報の対象の切り替え |
| 設定 `settings` | 同上 | 共有の範囲（オーナー）・日報の対象・日報のチェック項目（全店舗共通はオーナー、店舗だけの項目は店長も） |

管理者モード（スタッフ URL 無し）はオーナーと同じ範囲を見られる。自分のチャートは持たない。

## 見える範囲

旧ツールの「ブランド」を、このダッシュボードの「店舗」（設定 → スタッフ の所属店舗）に置き換えた。

| | 本人 | 同じ店舗の店長・マネージャー | オーナー・管理者 | 仲間（共有がオン） |
|---|---|---|---|---|
| チャート | 書く | 見る | 見る | 見る（今の売上・内訳のメモは除く） |
| 週報・AI のレビュー・コメント | 書く | 見る・コメント | 見る・コメント | **見えない** |
| 日報 | 書く（対象の人） | 見る・コメント | 見る・コメント | **見えない** |
| 進み具合（提出・実行率・フォーカス達成） | 見る | 見る | 見る | 集計だけ見る |

- 共有の範囲（オーナーが マンダラ → 設定 で決める）: **共有しない**（既定）/ **同じ店舗内** / **全店舗**
- 見せ合う機能なので **相互**: 自分を非公開にしている間は、仲間のチャートも見えない
- 権限はすべてサーバー（`api/_lib/mandala/handlers.js`・`shared/mandala.js` の `canViewMember` など）で判定する。ブラウザから Supabase へは直接触らない（テーブルは RLS を有効にしてポリシー無し）

## 構成

| 場所 | 内容 |
|---|---|
| `supabase/migrations/00006_mandala.sql` | テーブル（`mandala_*`）。日報の既定のチェック項目も入れる |
| `api/mandala/index.js` | API（GET/POST `/api/mandala?action=...`）。AI のために maxDuration 60秒 |
| `api/_lib/mandala/handlers.js` | 権限の判定と各処理 |
| `api/_lib/mandala/data.js` | DB の読み書き（1,000行を超える取得はページを分ける） |
| `api/_lib/mandala/ai.js` | Claude のプロンプト・ツール（構造化出力）・出力の検証・再試行 |
| `shared/mandala.js` | 週（月曜はじまり・日本時間）・チャートの集計・進み具合・見える範囲の判定 |
| `src/features/mandala/` | 画面 |
| `scripts/import-mandala-tool.mjs` | 旧ツールからのデータの移行 |
| `test/mandala.test.js` / `test/import-mandala.test.js` | テスト（見える範囲・保存・AI の再試行・移行） |

共有の範囲は `dash_config` の `mandala.settings` に保存する（`/api/db?table=dashConfig` からは読み書きできない）。

## 使い始めるまで

1. Supabase の SQL Editor で `supabase/migrations/00006_mandala.sql` を実行する（何度実行してもよい）
2. Vercel の環境変数（AI を使う場合）
   - `ANTHROPIC_API_KEY`（施術ツールの姿勢アドバイスと共通）。未設定でもマンダラは使える（AI のレビュー・提案だけ出ない）
   - `MANDALA_AI_MODEL`（任意。既定 `claude-sonnet-4-6`。旧ツールの `AI_MODEL` も読む）
3. デプロイ（関数は `api/mandala` が増えて 4本）
4. 旧ツールのデータを移す（下記）
5. 店長・オーナーが マンダラ → 設定 で、日報の対象・チェック項目・共有の範囲を確かめる
6. スタッフに「その他 → マンダラ（またはホームのカード）から週報を書く」ことを伝える。旧ツールは移行後は使わない

## 旧ツールからのデータの移行

```bash
# .env.local に 4つ書く（移す元 = 旧ツールの Supabase、移す先 = このダッシュボードの Supabase）
#   MANDALA_SUPABASE_URL=...   MANDALA_SUPABASE_SERVICE_ROLE_KEY=...
#   SUPABASE_URL=...           SUPABASE_SERVICE_ROLE_KEY=...
node scripts/import-mandala-tool.mjs                 # 確認だけ（対応付けと件数を出す）
node scripts/import-mandala-tool.mjs --map "三浦=st-miura"   # 名前で合わない人を staff.id で指定
node scripts/import-mandala-tool.mjs --apply         # 書き込む
```

- 旧ツールのメンバー（表示名）を、ダッシュボードのスタッフ（名前）に対応付ける。同じ名前 → 名前で始まる人が 1人（「佐藤」→「佐藤 美咲」）→ `--map` の順。候補が複数いても在籍中が 1人ならその人。合わない人は移さず一覧に出す
- 移すもの: チャート（テーマ・項目）・週報（行動のチェック・フォーカス・AI のレビュー・コメント）・応援・日報（チェック・コメント）・公開 / 日報の対象の設定・共有の範囲（ブランド内 → 同じ店舗内、グループ全体 → 全店舗）
- ID はそのまま使うので、何度実行しても同じ結果になる。ダッシュボードで先に書いた週・日の週報 / 日報はそちらを残す
- 日報のチェック項目は、同じ区分・同じ名前の項目に結びつける（全角・半角の違いは無視）。移す日報で使っていて、無い項目だけ「全店舗共通」として足す
- 旧ツールの KPI（`kpi_*`・`weekly_kpi_entries`）は移さない（旧ツールでも使っていない）

## 旧ツールから変えたところ

| 旧ツール | ダッシュボード |
|---|---|
| メール + パスワード（Supabase Auth） | スタッフ URL（管理者モードはオーナーと同じ） |
| ブランド（vivie / si'se / Mavie / titi） | 店舗（店長は担当店舗、マネージャーは管轄の複数店舗） |
| 「下書き保存」ボタン | 入力は自動で保存（保存の状態を画面の下に表示。閉じる前に未保存なら確認） |
| フォーカスは AI の提案の採用だけ | チャートの行動から自分でも選べる（今週・来週。検索つき） |
| スタッフは週報へのコメントを見られなかった | 自分の週報の下で店長・オーナーとやりとりできる |
| 連続提出は今週を出すまで 0週 | 今週がまだなら先週までの連続を数える |

| チャートの目標金額だけ | 今月の施術消化売上（SalonOne）を目標の横に並べる・現状の売上を SalonOne の平均から入れられる |
| — | 日報のチェック項目から 出納帳・施術ツール・週報 を開ける。店舗だけのチェック項目を足せる |
| — | 日報の提出も「日々の動き」に出る |
| 毎週月曜の下書きの自動作成（Cron）・メール通知 | 入れていない（ホームのカードと週のはじめのお知らせで代わりにする） |
